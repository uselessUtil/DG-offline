# 頭像圖集、HUD與技能橫條裁切的證據

整理日期：2026-10-27。來源S214–S216見 [來源清單](sources.json)。本頁補充 [r17 UI證據](V291_UI_EVIDENCE.md)：圖集中的頭像矩形、隊伍五格HUD、技能橫條是不同的座標契約；找到其中一種不表示找回另外兩種。本次僅整理既有調查，未重新解析資源、擬合或改寫顯示參數。

## DG0深度盤點找到了什麼

S214檢查本機DG0備份的240個檔案，解析86個UnityFS包、833個物件，沒有解析錯誤。63個unit包各只有Texture2D與AssetBundle，不能從它們推斷已保存完整角色Prefab或裁切主資料。

39個MonoBehaviour由33個UIAtlas、3個AnimationEvent、3個AnimationArray組成；46個材質沒有非預設的貼圖縮放／偏移。15個Mesh與12個AnimationClip屬報告列出的地圖包，不能把其UV當成角色立繪取景。

19份圖集JSON共3,152筆frame，沒有trimmed或rotated項目。例：`chara_icon_1327`在2048×2048圖集中的矩形為x=262、y=1042、128×128，UIAtlas與TexturePacker JSON一致；`spriteSourceSize`仍是完整128×128。這只表示小頭像在圖集中的位置，不表示該頭像位於完整角色立繪的哪一塊。

原始物件關鍵字搜尋沒有命中裁切欄位；序列化檔案僅在三個地圖包的型別schema找到offsety。關鍵字搜尋只是物件／型別檢查的補充，不能單獨證明資料不存在。此備份未找回逐角色HUD或技能橫條參數；結論不涵蓋其他備份、DG0完整客戶端或原伺服器。

## 技能橫條使用完整立繪的UV

S216追蹤原2.9.1的 `CutinObject.Setup → AssetAutoSetCharaTexture.SetCharaID → AssetBundleUtil.RequestCharaTexture`。原生取樣為：

| 量 | 計算 |
| --- | --- |
| 水平比例sx | img_cutin_tiling／1000 |
| 垂直比例sy | sx×9／60，即sx×0.15 |
| 水平偏移ox | img_cutin_offsetX／1000 |
| 垂直偏移oy | img_cutin_offsetY／1000 |
| 以左上角為原點的像素範圍 | left=ox×W；top=(1−oy−sy)×H；width=sx×W；height=sy×H |

W、H是完整立繪尺寸；網格UV範圍0～1，材質使用Clamp。這是取樣範圍的換算，若超出邊界還涉及Clamp，不應當作保證落在圖片內的一般裁切矩形。五格HUD的 `img_0..4` 與技能橫條的 `img_cutin_*` 不能混用。

## 頭像定位能提供參考，不能代替官方參數

調查以595個舊角色原始標註作參考；像素匹配誤差≤0.02的450個角色用於低誤差分組。頭像細節位置是原128px頭像中(30,18,100,100)範圍的匹配中心，不是經過人工標註的解剖學頭部中心。

五折依連續50個draw_id分組，只以各訓練折的低誤差樣本擬合。它與r17五格HUD按進化家族／共用draw_id分組的方法不同，不能直接互換指標或宣稱相同的分組隔離。

| 驗證範圍 | 角色數 | 留出樣本IoU中位數 | 尺度誤差中位數 | 垂直誤差／橫條高度中位數 |
| --- | ---: | ---: | ---: | ---: |
| 低圖像匹配誤差 | 450 | 72.19% | 9.24% | 6.18% |
| 全部舊角色 | 595 | 68.06% | 13.45% | 7.56% |

低誤差組的頭像細節寬度與橫條寬度相關係數約0.893；但原始tiling介於571～3000，仍有逐角色差異。相關性或像素匹配誤差不是校準後的信心機率，中位數也不代表最差案例品質。

指標比較的是矩形UV取樣範圍，不包含技能文字、背景、動畫或疊圖。報告辨識的「人類最強の戦士：リヴァイ」為fix_id1327、draw_id1321，位於舊595角色之外，沒有從舊標註恢復其原始橫條參數。圖鑑／角色ID、draw_id與圖集sprite名稱須分別核對，不能只靠相近數字認定相同素材。

本次未套用報告的推估結果。後續可把定位作為人工調整起點，但仍須逐角色查看構圖及原生顯示；工具入口見 [Battle Lab](../../tools/battle-layout/README.md)。來源清單保存報告與bundle盤點指紋，沒有搬入原始遊戲資源或研究圖片。
