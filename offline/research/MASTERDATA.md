# 主資料年代與 APK 相容性

本頁是截至 2026-10-23 的本機報告整理；來源編號見 [sources.json](sources.json)，使用界線見 [索引](README.md)。

## 來源年代與角色範圍

| 來源 | 已確認內容 | 使用限制 |
| --- | --- | --- |
| 1.0.5 原 APK | 449 個有效角色；本機後端要求的 28 份主資料均有內建對應 | 更早期研究基準，不是後期版本資料 |
| 1.0.6 原 APK | 522 個有效角色，圖鑑號並非連續 1–522 | 舊版角色／技能與玩法基準 |
| `jp.gungho.dg` 快取 | 596 列角色表，扣除零號列為 595 角；`draw_id=1..595` 無缺號 | 內容指向 2014 三月底、1.0.7 時期，不證明精確安裝版號 |
| DGDB SQL | 2,695 列角色表，2,694 有效角色；`draw_id=1..2694` 無缺號 | 無印後期彙整，不是單一官方 MasterData 快照 |
| `jp.gungho.dg(DG0)` 快取 | 有素材，但未找到主資料表或角色／技能／敵人資料容器 | 不能用本份備份補數值欄位；不能推論整個 DG0 遊戲沒有主資料 |

來源：S01–S05、S08。舊快取的最新角色為圖鑑 No.594／595「ノア／竜王ノア」，內部 ID 為 608／609；最大內部 ID 671 實際對應圖鑑 No.593。相對原 1.0.6 多 73 角，新增圖鑑號為 497–504、531–595。全部 595 角都有對應 prefab 名稱、立繪及頭像框，此為素材存在性核對。

角色實裝順序、Wiki 及快取索引 2014-03-27～03-31 UTC 共同支持三月底判定；上層索引另有時間值，不能拿來當整份備份日期。舊主表 CAB SHA-256 為 `b3c342f849beddf4a871d6bf06ca9502e44ede4a78d0409efb4aa45a5d16b586`（S02）。

DGDB 建議標籤為「無印後期彙整（角色至 No.2694／2017-05-26 追加批次；資料庫匯出 2017-09-21）」。角色表最大 `updated_at` 為 2017-06-15，部分技能表至 2017-08-31，關卡表至 2017-09-14；這些是資料站更新記錄，不能當成官方實裝日或 APK 版本。來源 checkout 為 `kennyfong19931/dgdb`、commit `1a15adf733bb02467d51303a110f361535a7b4bc`，檔案為 `external/dgdb/database/dump_20170921.sql`（S04、S05）。

## 舊快取原樣解析結果

S06 將容器實際引用的 28 張表交給各原版未修改的 LitJson 與列型別，未刪欄位、補表或改數值：

| APK | 成功 | 失敗 | 缺型別 |
| --- | ---: | ---: | ---: |
| 1.0.5 | 19 | 5 | 4 |
| 1.0.6 | 22 | 2 | 4 |
| 1.0.8 | 28 | 0 | 0 |
| 1.0.9 | 28 | 0 | 0 |
| 1.1.0 | 27 | 1 | 0 |
| 2.1.0 | 27 | 1 | 0 |
| 2.9.0 | 27 | 1 | 0 |

快取雖有 31 份 MasterData TextAsset，另三份未被容器引用；它們不能充作這 28 張有效表。角色、區域、任務表分別為 596、110、399 列，不能把所有列直接當成有效／可玩項目。

- 1.0.6 拒絕 EnemyChara 的 `act_table1` 與 StoreProduct 的 `active`，另缺四種表型別。
- 1.1.0 起 Area 不接受 `bgm_normal`／`bgm_boss`，需適配新音樂包欄位與載入流程。
- 1.0.8／1.0.9 通過解析不表示原 APK 會自動使用快取。CAB 是 SerializedFile，缺下載索引也影響定位。
- 快取缺抽卡、下載索引與公告等資料；1.0.9 原本機後端另有月登入／登入禮物需求。新版 Leader／Passive 欄位解析為零，不能因此宣稱新版技能已還原。
- 必殺技 `value_list` 等欄位由原轉換器產生；來源 JSON 未列出它們不一定是缺資料。

1.0.8 原 APK 另經獨立盤點：本機後端仍在，但要求的 32 份 Resources 主資料全部未內建；不能只切本機路由就完成創角（S08）。

## 原樣解析上限與核心玩法是不同問題

S07 補測「原 LitJson → 原必殺技轉換器 → 原活動初始化」，並核對技能 ID 與五個原參數：

| 版本 | 459 筆非零 ID 舊必殺技初始化 | 可下的結論 |
| --- | --- | --- |
| 1.1.0 | 423 成功、36 例外 | 首個例外需要完整戰鬥回復情境；不能直接判定資料不相容 |
| 2.1.0 | 459 成功 | 此段初始化及五個參數保留通過 |
| 2.9.0 | 459 成功 | 沒有原先懷疑的五格轉十六格越界 |

這些測試使用隔離的 Unity 入口替身，未驗證傷害、敵人 AI、完整戰鬥或 Android。尤其 `skill_damage_enable` 等新欄位的預設語意仍需驗證。**最高 1.0.9 只描述原樣解析，不能排除轉換後的 1.1.0／2.1.0／2.9.0。**

後續 2.1.0 已實作版本專用技能配接及候選版，但仍未完成全技能／戰鬥回歸；以 [2.1.0 現行說明](../v210/playable/README.md) 為準。

2.9.0 配接前研究見 [核心玩法確認](V290_OLD_CONTENT.md)：Area 兩欄調整後 28 表可解析，但舊倍率不會自動轉成新傷害欄位。後續 [r10 候選版](../v290/playable/README.md) 已實作舊技能邊界與素材轉換；完整戰鬥仍待驗證。2.4.0 的版本專用差異見 [候選版說明](../v240/playable/README.md)。

[4.0.0 後續研究](V400_OLD_CONTENT.md) 已還原兩份 DLL，以目標原 LitJson 驗證原樣 27／28、Area 調整後 28／28，459 筆技能可初始化但傷害新欄位仍為零；49 表需求對舊 28 表尚缺 21 表。這份研究不包含可玩 APK、完整後端或戰鬥驗證。後續 [4.0.0 r6 工程](../v400/playable/README.md) 改採原始 1.0.6 的 522 角色／371 列任務，已有候選 APK 與結構檢查，但 Android 與完整流程仍待驗證。

## DGDB 可提供的資料與缺口

S04 初期以「33 表」指有 INSERT 資料的表；S01 完整計入空的 `audio_data` 後為 **34 張定義表、33 張有資料**。

| 表 | 列數（含零號列，如有） | 用途 |
| --- | ---: | --- |
| unit / evo | 2,695 / 1,141 | 角色、進化 |
| l_skill / a_skill | 1,812 / 1,721 | 隊長技／必殺技 |
| n_skill / p_skill | 3,359 / 1,066 | 普通技／被動技 |
| skill_boost / status_ailment | 325 / 1,480 | Boost／狀態 |
| link_system / limit_over | 118 / 52 | Link／限界突破 |
| enemy / quest | 9,719 / 3,594 | 敵人／關卡目錄 |

`skill_active0/1` 引用 `n_skill`；`skill_limitbreak` 引用 `a_skill`。2,694 角的七類直接技能引用，以及進化前後角色／四個材料欄位未見非零 ID 缺失，但未檢查全部技能遞迴依賴。DGDB 的立繪、頭像以 `draw_id` 命名，不可直接套用舊遊戲內部 ID。

舊 595 角與 DGDB 雖可全數對應，但最大 HP 有 107 角、最大攻擊 123 角、Cost 67 角不同；隊長技 ID 19 角、必殺技 ID 21 角不同。保留 2014 玩法時不應被後期值覆蓋。

來源還缺角色 22 個顯示位置／尺寸欄位、敵人 7 個血條／位置欄位、普通技 `effect`／`skill_active`、進化 `active`、狀態 `clear_type` 等。圖片、SQL 與同名欄位不能替代原模型／動畫或證明枚舉語意相同。

關卡剔除零號列後有 3,593 筆，但只有 1,802 筆有樓層記錄，1,791 筆缺樓層。樓層至敵群、敵群至敵人的非零引用可對上；面板群組引用缺 52 個 ID，並缺舊版 CategoryPattern／ExpectPattern 原表。必須整組核對：

`area → quest → quest_floor → enemy_group → enemy`，連同面板、生成模式、行動與掉落。

S01 對 1.0.6 的 371 筆關卡記錄找到 360 個 DGDB 同 ID，缺 `383,389–393,420–424`；原樓層有 305 筆 `quest_id`、156 筆 `boss_group_id` 與 DGDB 不同，包含預留列。同 ID 命中不等於可玩覆蓋率。

## 承接 DGDB 的版本選擇

S01 共盤點 22 個 APK 加 1 個 XAPK 內嵌 APK，涵蓋 8 個原始版本／封存檔及 14 個離線衍生 APK。已映射的衍生版核心欄位與各自原版相同；注入的執行時資料不能僅靠 TextAsset 數量判斷。

| 目標 | 判讀 |
| --- | --- |
| 1.0.6 | 保留舊數值及玩法的基準；不具備新版敵人行動／技能機制 |
| 1.0.8～1.1.0 | 舊內容移植候選；不能承接整套後期技能 |
| 2.1.0 | 有副種族、追加技能及新版必殺技；缺 Boost／EnemyAbility 型別 |
| 2.9.0 | 已讀取 schema 中優先評估後期核心資料的候選；仍不是全 DGDB 可玩保證 |
| 4.0.0 紀念版 | 初查 DLL 被包裝；後續已還原並核實 49 表需求、部分 schema 與舊技能初始化。後續已有採原始 1.0.6 資料的 [r6 候選](../v400/playable/README.md)，Android 未驗證，不能判定完整 DGDB 可用；見 [歷史研究](V400_OLD_CONTENT.md) |
| 圖鑑 APK | 素材來源，不是遊戲引擎候選 |

2.9.0 仍缺 Link、限界突破等後期機制。47 筆必殺技的 `value5..15` 有非零值，68 角引用；原轉換器只保留前五格。72 筆普通技有新版 `ability` 參數組，68 角引用；不能因 Boost 型別存在就當成全部能力可用。2,284 角指定 Link 普通技，也不表示目標引擎能執行。

Boost／EnemyAbility 的十六格參數陣列由原轉換器產生，應與真正缺少的來源欄位區分。後期擴充應逐項標明「可直接對應」「需轉換」「需新增程式」「缺來源」，而不是把缺欄位自動補零。

## DG0 備份的明確界線

S03 檢查全部 240 檔（73,338,858 bytes）、86 個 UnityFS，均可解析；共 833 個 Unity 物件。20 個 TextAsset 是 19 個圖集 JSON 和 1 個影片，39 個 MonoBehaviour 是 UIAtlas／AnimationArray／AnimationEvent；未找到主資料容器。

98 個 Texture2D、5 個 AudioClip、15 個 Mesh、12 個 AnimationClip 可作素材候選，但無法補入副種族、新技能參數、敵人能力或血條數值。本結論僅針對這份備份；未將 Analytics 內容或私人資料搬入倉庫。
