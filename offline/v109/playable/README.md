## 建置與驗證

工具均在專案 Docker 環境執行。先選用含 UnityPy／Pillow 的 Python 環境，以下從倉庫根目錄呼叫：

```sh
python offline/v109/playable/build.py --output artifacts/1.0.9-offline-new
python offline/v109/playable/test.py artifacts/1.0.9-offline-new/build-report.json
```

輸入要求精確 1.0.9 APK hash，以及既有快取來源雜湊清單和綁定來源的靜態檢查紀錄。解包及生成資料置於倉庫外的暫存區，測試簽章私鑰另放專用持久儲存區；均不提交 Git。輸出目錄不存在才可新建；`--resume-work` 僅用於尚未產生 APK 且由 `work.txt` 綁定的同一建置。`--assets-from` 可重用前次報告綁定且主資料核心／備份來源相符的圖片與原生包，不能任意換資料集。

所需來源與先行紀錄：

- 原 1.0.9 APK 的精確 hash 由 `offline/v109/audit.py` 限定；1.0.6 捐贈來源及兩張卡池表的 hash 另由 `donor.py` 鎖定。
- `artifacts/1.0.9-security-audit/manual-review.json`、`clamav.txt` 與 [安全檢查](../SECURITY_REVIEW.md) 的 hash 綁定；既有紀錄必須與來源相符，不能以空檔取代。
- `artifacts/cache-backup-audit-2026-10-22/source-files.json` 與 `jp.gungho.dg/` 原快取，建置會逐檔核對。新增的其他裝置備份不會自動取代此來源。
- 生成組件及資料、舊版本交付與簽署私鑰不隨 Git 提供。欲更新安裝保留候選版存檔，須保留相同候選版簽署金鑰，不能沿用官方簽章。

腳本仍含工作根目錄、工具與簽署位置的固定預設，尚未完成跨配置參數化；執行前需依自己的隔離環境核對。共享 Runtime 的版本限定文字轉換使用明確比對，來源形狀或版本標記改變時會拒絕轉換，不能直接替換成任意新版 Runtime。

共享 Runtime.cs 與 FreeChipShop.cs 經明確版本轉換後，對原 1.0.9 Unity／BCL／遊戲 DLL 編譯；CollabGacha.cs 直接重用。獨立 Patch.cs／PatchCommerce.cs 保留目標方法形狀檢查。30 張資料表使用與圖片相同的 RVA 位元組封裝，避開舊編譯器字串容量與裁切 BCL 缺少資源串流 API 的限制。共享 native_bundles.create 的 1.0.6 預設覆蓋數未放寬；本版顯式指定 595 角色、106 地圖及目標腳本 hash。

既有驗證流程從實際簽署 APK 重新提取組件，檢查外部引用、原方法白名單、所有 PNG 雜湊與座標、90 份原生包內 CAB 的原位元組、創角到教學結算、392 個有效有樓層關卡生成、595 個角色兩個等級界限的數值計算，以及另一個程序重啟後讀回通關旗標／隊伍。
